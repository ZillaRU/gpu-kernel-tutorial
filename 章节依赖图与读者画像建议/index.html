    GPU Kernel 教程：章节依赖图与读者画像建议¶

    这页解决两个问题： 1. 章节之间到底怎么依赖； 2. 不同背景的读者，最省时间的阅读路径是什么。

    1. 章节依赖图¶

    先给出最重要的结构图：

    第一章：执行模型 / 分块 / 内存层级
    ↓
第二章：计算优化 / 融合 / 高级调度
    ↓
第三章：架构特定优化
    ↓
第四章：算子技能落地
    ↓
第五章：系统工作流闭环

    但这个图还不够细，真正的依赖关系更像这样：

    第一章 ------------------------------┐
  提供：执行模型、地址、mask、访存基础  │
                                      │
第二章 --------------------------┐   │
  提供：fusion / split-k / 调度框架 │   │
                                  │   │
第三章 ----------------------┐   │   │
  提供：平台差异修正            │   │   │
                              ▼   ▼   ▼
第四章：把 1~3 章方法落到具体算子上
                              │
                              ▼
第五章：把前面所有内容变成 profile→diagnose→optimize→verify→benchmark 的闭环

    核心意思是：

    • 第一章是地基；
    • 第二章是方法分流器；
    • 第三章是平台修正器；
    • 第四章是应用场；
    • 第五章是工作流闭环器。

    2. 如果你时间有限，至少要知道这件事¶

    不同读者最常见的低效做法是：

    • CUDA 新手直接跳 Flash-Attention；
    • 推理工程师上来就看架构特定细节；
    • 只会改参数，不会做 profile；
    • 看完很多算子，却不知道如何组织优化顺序。

    所以这页的目的就是：

    让你按自己的背景，走最短路线，而不是把 8 份文档平均用力。

    3. 读者画像 A：Triton / CUDA / HIP 初学者¶

    你通常的状态¶

    • 知道 GPU 并行很强；
    • 见过 Triton 或 CUDA 代码；
    • 但对 warp、tile、mask、stride、coalescing 没有稳定直觉。

    推荐顺序¶

    1. chapter1-tier1-tier2.md
    2. 最小可运行模板集.md
    3. 术语表与通用坑清单.md
    4. chapter2-tier3-tier4.md
    5. chapter5-system-skills.md
    6. 最后再进 chapter4-kernel-skills.md

    原因¶

    你现在最缺的不是某个高级算子，而是：

    • 基本执行模型；
    • 正确地址表达；
    • 对 mask / stride / reduce dtype 的底线意识。

    你的最低目标¶

    能自己读懂并解释“最小 Triton 向量加法”和“最小 Softmax / RMSNorm 骨架”。

    4. 读者画像 B：已经会写 kernel，但优化还靠试错¶

    你通常的状态¶

    • 能写出正确结果；
    • 也知道要调 block size / num_warps；
    • 但每次优化都像撞大运；
    • 回归了也说不清是哪里坏了。

    推荐顺序¶

    1. chapter5-system-skills.md
    2. chapter2-tier3-tier4.md
    3. chapter1-tier1-tier2.md
    4. 术语表与通用坑清单.md
    5. chapter4-kernel-skills.md
    6. 最后读 chapter3-tier5-arch.md

    原因¶

    你现在最缺的不是技巧，而是：

    • 优化流程；
    • 诊断优先级；
    • 一次只改一个点的工程纪律。

    你的最低目标¶

    拿到一个慢 kernel 时，先 profile，再决定动 Tier 1/2/3/4/5，而不是直接开调参数。

    5. 读者画像 C：只关心大模型推理算子¶

    你通常的状态¶

    • 主要关心 GEMM、Flash-Attention、RMSNorm、RoPE、MoE、FFN；
    • 目标是把推理吞吐或单 token latency 打下来；
    • 更在乎“该先优化哪个算子”。

    推荐顺序¶

    1. chapter4-kernel-skills.md
    2. chapter5-system-skills.md
    3. chapter1-tier1-tier2.md
    4. chapter2-tier3-tier4.md
    5. chapter3-tier5-arch.md

    原因¶

    你最需要的是：

    • 先建立算子分类；
    • 再补工作流；
    • 然后回补底层原因。

    你的最低目标¶

    对 GEMM、Flash-Attention、Softmax、RMSNorm、MoE 这 5 类算子，能快速说出主瓶颈与第一优先优化方向。

    6. 读者画像 D：主要做 NVIDIA 平台优化¶

    你通常的状态¶

    • 设备主要是 4090 / A100 / H100；
    • 会频繁看 Nsight Compute / Nsight Systems；
    • 更关注 Tensor Core 路径与数据搬运重叠。

    推荐顺序¶

    1. chapter1-tier1-tier2.md
    2. chapter2-tier3-tier4.md
    3. chapter3-tier5-arch.md
    4. chapter4-kernel-skills.md
    5. chapter5-system-skills.md

    你的重点章节¶

    • 第一章：地址/分块/访存基础
    • 第二章：fusion / Split-K / persistent
    • 第三章：Ampere / Ada / Hopper 差异

    你的最低目标¶

    能分清哪些优化是跨平台共性，哪些是 Hopper/Ampere 语境下才成立的“局部最优”。

    7. 读者画像 E：主要做 AMD / MI300X / ROCm 平台优化¶

    你通常的状态¶

    • 更关心 wavefront-64、MFMA、ROCm profiler；
    • 经常遇到“在 CUDA 教程里说得通，在 ROCm 上却不对劲”的情况。

    推荐顺序¶

    1. chapter1-tier1-tier2.md
    2. chapter3-tier5-arch.md
    3. chapter2-tier3-tier4.md
    4. chapter4-kernel-skills.md
    5. chapter5-system-skills.md

    原因¶

    你最需要先建立的是：

    • 共性基础；
    • 然后立刻补平台差异；
    • 再回来看 fusion / scheduling 怎么在 ROCm 语境里落地。

    你的最低目标¶

    不再把“CUDA 上的默认直觉”原封不动套到 ROCm/MI300X 上。

    8. 读者画像 F：做代码评审 / 团队知识建设的人¶

    你通常的状态¶

    • 不一定亲自写每一个 kernel；
    • 但要 review、做规范、带新人；
    • 需要一份统一口径的知识底座。

    推荐顺序¶

    1. 术语表与通用坑清单.md
    2. chapter5-system-skills.md
    3. 学习路径-总目录.md
    4. chapter1-tier1-tier2.md
    5. chapter4-kernel-skills.md

    原因¶

    你最值钱的角色，是帮团队建立：

    • 统一术语；
    • 统一 review checklist；
    • 统一 optimize-loop 纪律。

    你的最低目标¶

    能用一套统一 checklist 对 kernel PR 做高质量 review。

    9. 快速选路表¶

    如果你不想看长解释，可以直接按这个表：

    你是谁 最推荐起点
    GPU kernel 初学者 第一章
    已会写 kernel，但不会稳定优化 第五章
    只关心大模型推理算子 第四章
    NVIDIA 优化工程师 第一章 → 第二章 → 第三章
    AMD / ROCm 优化工程师 第一章 → 第三章
    reviewer / 团队知识维护者 术语表与通用坑清单

    10. 建议你如何组合使用这些文档¶

    这里给一套很实用的组合：

    组合 1：看章节时¶

    • 主章节正文；
    • 同章配套模板；
    • 术语表；

    这样不会只停留在概念层。

    组合 2：写 kernel 时¶

    • 第四章算子技能；
    • 第五章系统流程；
    • 通用坑清单；

    这样最接近真实工作流。

    组合 3：做 review 时¶

    • 术语表与通用坑清单；
    • 第五章 optimize loop；
    • 对应算子章节。

    11. 如果你只打算记住一句话¶

    那我希望你记住的是：

    先选对阅读路线，再选对优化路径；不要在错误的抽象层上过度努力。

    这句话同时适用于学习，也适用于真正做 kernel 优化。
